The Shewhart Cycle

PDCA and PDSA — iterative continuous improvement

Goal

Describe the four phases of the Shewhart Cycle, explain the difference between PDCA and PDSA, and apply the cycle to a realistic improvement scenario.

Concept

Walter Shewhart (1930s) introduced this scientific, iterative approach to improvement. Deming later popularised it worldwide. The cycle never truly ends — each iteration builds on the last.

1 — PLAN

  • Identify the problem
  • Collect baseline data
  • Set SMART objectives
  • Develop action plan and prediction

2 — DO

  • Execute on a small scale (pilot)
  • Document observations
  • Limit risk — don't change everything at once

3 — STUDY / CHECK

  • Measure and collect data
  • Analyse with control charts and statistics
  • Compare against objectives
  • Understand why results occurred

4 — ACT

  • If it worked: standardise the change
  • If it didn't: adjust and restart
  • Start the next improvement cycle

PDCA vs PDSA: Deming preferred Study over Check. "Check" implies a pass/fail test. "Study" demands understanding why the results happened — the learning that makes the next cycle better. PDSA is now the preferred form.

Control charts in PDSA: They are essential in the Study phase — they distinguish real improvements from random variation. Without a control chart, you cannot tell if a change actually worked.

Example — ETL Pipeline Error Rate

PLAN

Baseline error rate = 2.8%. Target: < 0.5%. Hypothesis: 80% of errors from 2 data sources with 12% missing values.

DO

Deploy improved null-handling rules to staging pipeline for 2 weeks on 10% of records.

STUDY

p-chart confirms error rate drops to 0.4% (statistically significant, p < 0.05). Root cause confirmed.

ACT

Deploy to production. Update runbook. Start next cycle targeting the remaining 0.4%.
